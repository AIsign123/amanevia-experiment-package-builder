# Amanevia 実験パッケージ・ビルダー(試作)

ブラウザで実験を選び、条件と装置モジュールを組み合わせて**実験パッケージ**を作り、**ガードレール**で事前検査するWebサービスの試作です。

> **注意:** 物質データ・上限値・規則はすべて説明用の仮データです。安全性の認証を受けたものではありません。実機で運用する前に、必ず専門家(安全管理者・法令担当)が規則を確認・整備してください。

## できること

1. **実験を選ぶ**: 検証済みテンプレート(液体組成スクリーニング、触媒前駆体、粉体混合、薄膜コーティング)
2. **条件を入れる**: 溶媒、量、試料数、温度など(範囲外は自動で検出)
3. **装置モジュールを選ぶ**: 交換式モジュール。「推奨を自動選択」も可能
4. **手順を確認**: 条件から手順を自動生成
5. **ガードレールで判定**: `自動実行可` / `要承認` / `実行不可` の3区分と、指摘ごとの対応案
6. **承認と出力**: 要承認は承認者名の入力後にのみ出力可。実行不可は出力不可。JSON(内容のSHA-256付き)とMarkdownを出力

## 動かし方

依存パッケージはありません。

```bash
npm start        # http://localhost:8080 で開く(python3 が必要)
npm test         # エンジンのテスト(Node 20 以上)
```

`index.html` を直接開くとES Modulesの制約で動かないため、上記のようにHTTPサーバー経由で開いてください。
GitHub Pages で公開する場合は `.github/workflows/pages.yml` を使います(リポジトリの Settings → Pages で「GitHub Actions」を選択)。

## 構成

```
index.html
src/
  data/        物質・装置モジュール・実験テンプレートの定義(ここを整備して拡張)
  engine/
    guardrails.js   ガードレール検査(純粋関数)
    package.js      パッケージ生成・推奨モジュール・承認・出力
  ui/          ブラウザUI
tests/         エンジンのテスト(node:test)
docs/          設計メモ
```

## ガードレールの規則(現状)

| 区分 | 規則 |
|---|---|
| 実行不可 | 必要な装置モジュールが未選択 / 未登録の物質 / 自動化対象外の物質 / 併用禁止の組み合わせ / 使用量が上限超過 / 加熱が装置上限超過 / 溶媒の沸点付近まで加熱 / 48時間超 / 揮発性・有毒・微粉体で囲い込み(ドラフト等)が無い / 条件が範囲外 |
| 要承認 | 使用量が自動実行の上限超過 / 可燃性物質を60℃以上で加熱 / 12時間超 / 試料数が96超 / 未検証の手順 |
| 情報 | 腐食性物質(耐薬品仕様の確認) |

上限値は `src/engine/guardrails.js` の `LIMITS` で管理しています。

## 設計上の方針

- **安全側の規則は画面から緩められない**: 規則はコードとデータで管理し、UIに上限の編集機能を置いていません。
- **変更したら承認は取り消し**: 条件・装置を変更すると承認は無効になります。
- **判定は純粋関数**: `evaluate()` は副作用がなく、テストしやすい構造です。

## 次の段階(案)

- 実機・デジタルツインとの連携(出力JSONを実験キューへ登録)
- 実行中の監視(センサ閾値での自動停止)とのルール共有
- 物質データベースをSDSと連携して管理(出典・更新日・承認者を保持)
- ユーザー認証・権限(承認者の本人確認、承認ログ)
- 規則の変更履歴と、複数人承認
